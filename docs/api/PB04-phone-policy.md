# PB-04 전화번호 위험 판정·결과 검증 명세 초안

작성일: 2026-11-03 (KST). 범위: AI 파트의 정책 명세와 합성 테스트 사례.
전화번호 조회 API·서비스 정책 실행기는 구현하지 않았다. 별도 합성 조건 평가 실험
모듈만 제공한다. 최종 서비스 정책이나 wire 계약의
승인 문서가 아니며, 실행 위치(AI/BE)와 담당 경계는 협의 대상이다.

## 1. 기존 구조와 적용 경계

현재 src/image_analysis는 이미지 생성·변조 신호를 분석한다. policy.py의 임계값,
overall.py의 의심 우선 규칙, schemas.py의 ModelResult는 전화번호에 적용하지 않는다.
이미지 점수는 사기 확률이 아니며 전화번호 점수로 변환·합산하지 않는다.
기존 이미지 API의 필드·자료형·null 규칙·상태·정책 버전은 그대로 유지한다.

## 2. 작업 원칙과 미확정 정책

이번 작업에서 고정하는 원칙(최종 서비스 정책 승인과 구분):

- 실제 근거 없는 점수·신고 건수·신고 이력·근거 문구를 생성하지 않는다.
- 신고 0건, 빈 목록, 조회 자료 없음만으로 안전 판정하지 않는다.
- 조회 완료 여부와 위험 판단 가능 여부를 분리한다.
- 누락된 값이나 실패를 0점·신고 0건·정상 판정으로 대체하지 않는다.
- 테스트 fixture는 합성임을 표시하고 실제 번호·제공자·신고 사건을 넣지 않는다.

미확정: 제공자, 지원 번호, 근거별 신뢰도, 유효기간, 위험·주의·안전의 구체적 조건,
임계값, 점수 제공 여부, 충돌 우선순위, 공개 필드·enum·HTTP, 정책 실행 위치.
정책이 없으면 최종 위험 단계를 추측하지 않고 미확정으로 남긴다.

## 3. 판정에 필요한 근거와 한계

| 근거 항목 | 확인할 내용 | 신뢰도·한계 |
| --- | --- | --- |
| 출처 | 제공자 식별, 데이터 수집·검증 방식, 이용 범위 | 공식 출처라도 완전성·무오류를 보장하지 않음 |
| 번호 일치 | 정규화된 대상 번호와 조회 결과의 일치 | 유사 번호·부분 일치로 대상의 위험을 단정하지 않음 |
| 조회 시점·자료 시점 | 조회 완료 시각, 근거 발생·갱신 시각 | 조회 시각이 최근이어도 자료 자체는 오래될 수 있음 |
| 근거 종류·검증 상태 | 신고, 검증된 조치, 제공자의 분류 등의 구분 | 미검증 신고와 확인된 사실을 같은 무게로 취급하지 않음 |
| 범위·완전성 | 자료 없음의 의미, 조회 기간·대상, 누락 가능성 | 미등록은 안전의 증거가 아님 |
| 중복·독립성 | 동일 사건·출처의 중복 여부 | 복제된 신고를 독립 근거로 세지 않음 |
| 적용 정책 | 근거 해석 규칙과 버전, 검증 결과 | 정책 미확정이면 분류 확정 불가 |

번호 재할당·명의 도용·발신번호 변작 등으로 번호 관련 근거가 현재 발신자의 신원이나
통화 내용의 사기를 입증하지는 않는다. 제공자 선정 후 실제 보장 범위를 확인해야 한다.
신뢰도를 임의의 숫자로 부여하거나 점수 가중치를 만들지 않는다.

## 4. 판정의 의미와 결정표

- 위험: 승인된 정책이 유효한 위험 근거를 충족한다고 판단한 상태. 범죄 확정이 아니다.
- 주의: 승인된 정책상 주의가 필요한 근거가 있는 상태. 위험과의 경계는 미확정이다.
- 안전: 승인된 정책이 정한 조회 범위·시점에서 안전 조건을 충족한 상태라는 개념 후보.
  안전 판정 자체의 제공 여부도 미확정이며 무위험·신원 인증을 뜻하지 않는다.
- 판단 불가: 조회는 완료했으나 자료 또는 적용 정책이 부족해 위험 단계를 정할 수 없음.
  조회 실패는 별도 기술적 실패이며 같은 원인으로 묶지 않는다.

| 사례 ID | 조건 | 유지할 구분·처리 원칙 | 최종 판정 |
| --- | --- | --- | --- |
| risk_evidence | 유효한 위험 근거 존재 | 출처·대상·시점·정책 적용 가능성 확인 | 미확정: 근거→단계 매핑 필요 |
| suspicious_evidence | 일부 의심 근거 존재 | 미검증·불완전 근거의 한계 보존 | 미확정: 주의/판단 불가 기준 필요 |
| no_data | 조회 성공, 자료 없음 | 정상 조회와 자료 부재 보존, 안전 금지 | 판단 불가 원칙, wire 표현 미확정 |
| zero_reports | 신고 0건만 주어진 조건 | 0건을 안전·0점으로 변환 금지 | 미확정: 안전 기대값 금지 |
| insufficient | 근거 부족 | 부족 사유를 보존 | 판단 불가 원칙, wire 표현 미확정 |
| conflicting | 근거 충돌 | 임의 우선순위·평균 점수 금지 | 미확정: 충돌 해소 정책 필요 |
| lookup_failure | 조회 실패 | 정상 조회·자료 없음과 분리 | 판정 생성 금지, 오류 계약 미확정 |
| timeout | 조회 timeout | 시간 초과 원인 보존 | 판정 생성 금지, 오류 계약 미확정 |
| malformed | 잘못된 응답 형식 | 판정 입력으로 사용 금지, 기본값 보충 금지 | 판정 생성 금지, 오류 계약 미확정 |
| policy_pending | 적용 정책 미확정 | 근거가 있어도 승인된 매핑 없음 | 미확정 상태 유지 |

자료 없음은 유효한 응답이 비어 있다는 뜻이다. 실패·timeout·형식 오류에서는 자료가
없는지조차 알 수 없다. 정상 조회를 위험 판정의 성공과 동일시하지 않는다.

## 5. 결과 검증 기준

아래는 계약 검토용 의미적 요구사항이다. 실제 필드명·배치·필수 여부는 팀 합의 전이다.

| 분류 | 필요한 의미 | 검증 기준 |
| --- | --- | --- |
| 필수 후보 | 결과 연계 식별자, 처리/조회 상태 | 요청과 결과 연결, 허용된 상태만 수용 |
| 필수 후보 | 판정 가능 여부와 사유 | 자료 부족과 기술적 실패가 구별되어야 함 |
| 조건부 필수 후보 | 근거·출처·자료 시점·정책 버전 | 확정 판정 제공 시 추적 가능한 근거와 승인된 정책 필요 |
| 선택 후보 | 제공자 원점수·신고 건수 | 실제 제공·의미 검증 시만 사용. 미제공 시 생성 금지 |
| 미확정 | 표시 점수·verdict·공개 오류 코드 | 이미지 계약에서 필드명·단위를 복사하지 않음 |

null은 계약에서 정의한 '값 없음/판정 불가/비적용' 중 하나여야 한다. 누락은 선택 필드
미제공 또는 계약 위반을 의미할 수 있다. 필수 필드 누락과 명시적 null을 동일시하지 않는다.
실패에서 null을 허용할지 필드를 생략할지도 아직 미확정이다.

합의 후 검증할 항목:

- 문자열/숫자/정수/boolean을 구분하고 암묵적 변환을 금지한다.
- 점수를 도입하면 유한값과 제공자 계약의 범위를 검증한다. 0~1/0~100을 미리 가정하지 않는다.
- 건수를 도입하면 계약상 비음수 정수인지 확인한다. 누락·null을 0으로 바꾸지 않는다.
- 판정 불가·실패에 확정 위험 단계나 생성된 점수가 섞이지 않는지 확인한다.
- 시각·정책 버전·요청 연계와 상태 간 모순을 확인한다. 자료 유효기간 수치는 미확정이다.
- 알 수 없는 필드·enum의 거부/보존 방식을 계약으로 정한다.
- 기존 이미지 rawScore는 object|null, displayScore는 integer|null, decision과 status는
  기존 계약 그대로 유지한다. 전화번호 결과를 이미지 ModelResult에 끼워 넣지 않는다.

## 6. 합성 테스트 사례와 검증 수준

사례: tests/fixtures/pb04_policy_cases.json
검사: tests/test_pb04_policy_cases.py

fixture는 실제 Provider 응답이나 제품 JSON이 아닌 추상 시나리오 목록이다.
전화번호·신고 사건·건수·점수·제공자 이름을 포함하지 않는다. zero_reports도
조건 이름만 나타내며 신고 데이터 객체를 생성하지 않는다.
모든 expectedVerdict는 null이며 최종 판정 미정이라는 fixture 전용 의미다.
제품 API의 null 규칙을 정의하지 않는다. reviewRequirement는 검토 의무이며 판정값이 아니다.

자동 검사는 시나리오 누락, 합성 표시, 임의 기대 판정·점수·신고 필드 혼입을 검출한다.
기존 test_pb04_policy_cases.py는 정책 실행기를 호출하지 않는 사례 일관성 검사다.
아래 별도 실험 테스트도 실제 위험 정확도나 서비스 JSON 계약을 검증하지 않는다.
계약 확정 후 null/누락/잘못된 타입/NaN/무한대/음수/상태 모순을 포함한 실제
validator 테스트로 확장해야 한다. 현재 검사 통과를 전화번호 기능 완료로 보고하지 않는다.

### 독립 실험 모듈

src/phone_policy_experiment.py의 evaluate_synthetic_scenario는 네트워크·DB·이미지
코드에 의존하지 않는 순수 함수다. tests/test_phone_policy_experiment.py에서 기존
10개 fixture의 lookup/evidence만 추출해 synthetic=true와 함께 전달한다.
fixture의 expectedVerdict=null은 그대로 유지하며 서비스 판정값으로 사용하지 않는다.

실험 입력은 synthetic, lookup, evidence 3개 필드만 허용한다. 모두 필수이며 null과
누락을 거부한다. synthetic은 정확히 boolean true여야 하며 나머지는 지정된 문자열
조건이어야 한다. 알려지지 않은 필드·값·상태 조합, 번호·점수·신고 필드는 거부한다.
이 표시는 추상 조건만 받기 위한 제약이며 실제 데이터의 출처를 인증하는 장치는 아니다.

| 조건 | 실험 processing_status | 실험 verdict | 실험 reason |
| --- | --- | --- | --- |
| completed + absent | COMPLETED | INCONCLUSIVE | NO_DATA |
| completed + insufficient 또는 zero_reports_condition_only | COMPLETED | INCONCLUSIVE | INSUFFICIENT_EVIDENCE |
| completed + conflicting | COMPLETED | INCONCLUSIVE | CONFLICTING_EVIDENCE |
| completed + risk_candidate/suspicion_candidate/unmapped | COMPLETED | INCONCLUSIVE | POLICY_UNCONFIRMED |
| failed + unavailable | FAILED | null | LOOKUP_FAILED |
| timeout + unavailable | FAILED | null | LOOKUP_TIMEOUT |
| invalid_response + unusable | FAILED | null | INVALID_RESPONSE |

모든 결과의 policy_status는 UNCONFIRMED다. 위험·주의·안전은 반환하지 않는다.
이는 정책 미확정 상황의 실험 동작이며 최종 단계 매핑을 승인한 것이 아니다.
lookup/evidence를 결과에 보존하며 점수·신고 데이터는 만들지 않는다.
잘못된 함수 입력은 ValueError로 거부한다. 유효한 입력이 외부 응답 형식 실패라는
시나리오를 나타내면 FAILED/INVALID_RESPONSE를 반환한다. 실제 응답 파서는 아니다.
에러에는 입력 원문을 포함하지 않는다.

결과는 불변 dataclass이며 공개 HTTP/JSON 계약이 아니다. INCONCLUSIVE와 실패의 null,
필드명·상태명은 이 실험에만 적용한다. 기존 이미지 API에는 아무 변경도 하지 않는다.
실험 검사는 정상 조건 처리·자료 없음·부족·충돌·정책 미확정·기술 실패 및 입력 검증을
확인하며 실제 신고 데이터의 유효성, 위험도 정확도, 서비스 연동을 검증하지 않는다.

## 7. 역할과 남은 작업

AI: 근거의 의미·한계, 판정 결정표, 판단 불가 원칙, 합성 사례·검증 기준 제안.
BE: 조회 Provider·번호 검증·인증·재시도·API projection·DB·보관·사용량 구현.
공동: 정책 승인, 최종 계약, 정책 실행 위치, 데이터 기반 정확도·오탐·미탐 평가.

외부 API 없이 명세·사례 검증은 가능하지만 실제 위험 정확도 검증은 불가능하다.
담당 경계와 계약 확정 후 필요한 위치에 제품 정책·결과 검증기를 구현한다.
AI/BE 양쪽에 같은 정책을 독립적으로 중복 구현하지 않는다.
