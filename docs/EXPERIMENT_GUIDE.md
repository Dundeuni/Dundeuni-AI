# 이미지 분석 실험 설계·평가·기록 가이드

모델 비교와 서비스 적용 가능성 검증에 사용하는 공통 기준이다. 각 실험의 구체적인 모델·데이터·수량·판정 후보·목표는 해당 실험 계획과 결과 문서에 기록한다.

이 문서는 이미 수행한 실험 기록을 대체하거나 고정된 평가 규칙을 소급 변경하지 않는다.

## 1. 분석 범위

- AI 생성 탐지와 변조 탐지는 별도 문제로 평가한다.
- 이미지 내용의 사기 위험을 생성·변조 탐지 점수와 합치지 않는다.
- 변조 탐지 결과만으로 AI를 사용한 편집인지 확정하지 않는다.
- 모델 점수를 보정·검증 없이 실제 확률로 표현하지 않는다. 낮은 점수도 원본 인증을 의미하지 않는다.

## 2. 테스트 설계

- 무엇을 비교·검증할지와 완료할 산출물을 실행 전에 정한다.
- 모델명·공식 코드 버전·최종 가중치 파일과 해시·공식 전처리를 확인한다.
- 데이터 출처·이용 조건·선정 목록·라벨·변조 마스크를 확인한다.
- 설정용과 검증용을 분리하고 같은 원본·장면·파생본의 분할 중복을 점검한다.
- 모델 학습 자료와의 중복 등 확인하지 못한 사항은 한계로 기록한다.
- 원본·압축·축소·화면 등 평가할 입력 조건을 정한다.
- 판정 후보·선정 목표·지표·실패 및 보류 처리·평가 분모를 미리 정한다.
- 입력 변형을 코드로 재현한 경우 실제 앱·기기 캡처 평가와 구분한다.

## 3. 추론과 평가

- 모델 제작자가 제공한 전처리를 기준으로 실행한다. 입력 변형과 모델 전처리 변경을 구분한다.
- 정답 라벨·마스크는 평가에만 사용하고 예측에 영향을 주지 않도록 한다.
- 이미지와 마스크의 기하 변환·예측 지도의 좌표·크기를 확인한다.
- 추론은 모델의 평가 모드와 사용하는 환경에 맞는 gradient 비활성화 방식으로 실행한다.
- GPU 장치·정밀도·배치 크기·Python·라이브러리 버전을 기록한다.
- raw score와 변환된 점수를 구분하고 sigmoid 같은 변환을 중복 적용하지 않는다.
- NaN·무한대·잘못된 범위·실행 실패를 유효 점수나 정상 판정으로 바꾸지 않는다.
- 위치 지도만 반환하는 모델의 이미지 전체 집계 점수는 공식 분류 점수와 구분한다.
- 판정 기준은 설정용에서 평가·고정한 뒤 검증용에 적용한다.
- 검증 결과를 보고 모델·기준을 다시 선택하면 기존 자료를 새로운 독립 검증으로 주장하지 않는다. 변경된 선택을 최종 확인하려면 별도 검증 자료를 준비한다.

## 4. 결과 분석과 기록

- 입력 수·정상 처리·실패·보류·실행 시간·자원 사용량을 기록한다.
- 생성 탐지와 변조 판정의 오탐·미탐·보류, 변조 위치의 F1·IoU 등을 목적에 맞게 비교한다.
- 데이터셋·생성기·입력 조건별 결과와 주요 오류를 확인한다.
- 같은 원본의 생성·편집·변형 결과를 독립 원본 수로 계산하지 않는다.
- 소규모 표본과 그룹 관계, 결과의 불확실성을 기록한다.
- 목표를 만족하는 후보가 없으면 미선정 사실과 이유를 남긴다.
- 성능이 부족하더라도 계획한 평가와 분석을 마치고 근거를 기록하면 해당 검증 작업을 완료할 수 있다.
- 코드·데이터·전처리·판정 기준이 바뀌면 변경 이유와 비교 가능한 범위를 기록한다.

결과 문서에는 실험 목적·모델·환경·데이터와 분할·입력 조건·판정 규칙·실제 실행 명령·결과·오류·한계·후속 과제를 포함한다.

## 5. 실험 버전과 자산 보존

- 기존 실험의 목록·고정 기준·점수·지도를 덮어쓰지 않고 새 실험은 별도 경로에 기록한다.
- v0.1·v0.2 등 실험 버전의 구성과 결과를 구분해 보존한다.
- 실행 코드 상태를 확인할 수 있는 커밋에는 실험 버전 태그를 사용할 수 있다. 태그가 과거 실행 코드를 자동 복원하는 것은 아니다.
- Git에서 제외된 데이터·가중치·결과는 별도 위치와 해시를 관리한다.
- 코드의 공백·줄바꿈·인코딩 변경도 해시를 바꿀 수 있으므로 고정된 코드와 공식 소스의 자동 포맷에 주의한다.
- 무작위 시드를 기록하되 서로 다른 장비에서 모든 출력이 비트 단위로 같다고 가정하지 않는다.
- 재현은 기존 구성의 실행·계산 확인이며, 이미 알고 있는 자료의 재실행을 새로운 독립 성능 검증으로 표현하지 않는다.

## 6. 적용 범위와 연동 문서

- 실제로 검증한 입력 조건과 아직 평가하지 않은 조건을 구분한다.
- 지원 입력의 형식·해상도·압축·사진 영역 처리와 모델의 제약을 정리한다.
- 판정·보류·추론 실패·부분 완료의 의미와 위치 지도 좌표를 입출력 문서에 명시한다.
- 모델별 결과를 별도로 설명하고 검증하지 않은 시각적 이유를 생성하지 않는다.
- 서비스 적용 모델·판정 기준·지원 입력을 확정한 결과와 실험용 비교 기준을 구분한다.

문서 작성·공유·리뷰 흐름은 [Git 협업 규칙](../GIT_CONVENTION.md)을 따른다. 실행 코드 작성 기준은 [Python 코드 규칙](../CODE_CONVENTION.md)을 따른다.
