# 원래 데이터 구성 Baseline 후속 검증

2026-10-02 사용자 제공 CSV의 공식 TIFF 링크로 RAISE 40장을 확보해 B-Free 원래 80장·변형 400장 검증을 완료했다. 최신 결과는 [B-Free 보고서](BFREE_ORIGINAL_RESULTS_20261002.md)이다. 아래 RAISE 대기 상태는 이 보고서 작성 당시 기록이며 TruFor 원본 결과·고정 기준은 유지했다.

2026-10-01 현재 VS Code의 Windows 작업 폴더에서 실행한 후속 실험이다. **TruFor 80장 구성과 고정 기준의 최종 40장 검증을 완료했다. B-Free 원래 80장 검증은 RAISE 원본 확보 대기이다.** 기존 [보조 평가 보고서](BASELINE_RESULTS_20261001.md)의 결과와 구분한다.

이후 같은 원본의 TruFor 파생 입력 400장과 두 모델 CPU 4장씩을 정상 처리했다. [변형·CPU 보고서](ROBUSTNESS_AND_CPU_RESULTS_20261001.md)에 후속 탐색 결과를 분리해 기록했다. 아래 최종 점수·정책을 변경하지 않았으며 실제 앱/기기 입력·동시 요청은 미검증이다.

## 1. 결과와 판단

| TruFor 분할 | 데이터·유효 입력 | AUROC | A 오탐 / 음성 | A 미탐 / 양성 | B 오탐 / 음성 | B 미탐 / 양성 | B 보류 / 전체 |
|---|---|---:|---:|---:|---:|---:|---:|
| 조정용 | Columbia 원본 20·합성 20이다. | 0.9975 | 1/20 = 5% | 0/20 = 0% | 1/20 = 5% | 0/20 = 0% | 1/40 = 2.5% |
| 최종 확인용 | COVERAGE 원본 20·복사 붙여넣기 20이다. | 0.8275 | 1/20 = 5% | 9/20 = 45% | 1/20 = 5% | 7/20 = 35% | 6/40 = 15% |

두 분할 모두 추론 실패 0건이다. 최종 확인용 B의 보류는 양성 4장·음성 2장이다. A는 변조 20장 중 11장을 의심으로 판정했고, B는 9장을 의심으로 판정했다. B의 미탐 감소만으로 성능이 개선되었다고 판단하지 않는다. 보류는 탐지 성공이 아니다.

Columbia의 높은 결과가 COVERAGE의 복사·붙여넣기로 이어지지 않았다. **현재 공식 가중치와 고정 A 기준에서는 해당 COVERAGE 표본의 변조 9/20장을 놓쳤다.** 낮은 점수를 원본 인증으로 사용하거나 이 결과로 최종 서비스 기준을 확정할 근거가 부족하다. 최종 점수를 확인한 뒤 임계값을 바꾸지 않았다.

표본 수가 작은 초기 검증이다. 최종 확인용은 정책 조정 자료와 분리되어 있으나 데이터셋 분포가 달라 일반화 성능의 전체 추정으로 해석하지 않는다. 실제 사기 확률을 측정한 것이 아니다.

## 2. 위치 성능

지도는 공식 방향의 `map >= 0.5`이며 반전·리사이즈·경계 제외를 적용하지 않았다. 변조 이미지별 IoU·픽셀 F1의 평균이다. 이미지 전체 score 판정으로 위치 평가 대상을 걸러내지 않았다.

| 분할·정답 마스크 | 변조 입력 | 평균 IoU | 평균 픽셀 F1 |
|---|---:|---:|---:|
| Columbia 조정용·붙여넣은 카메라 영역이다. | 20 | 0.824213 | 0.877303 |
| COVERAGE 최종·공식 `*forged.tif`이다. | 20 | 0.529060 | 0.602722 |

Columbia 전체 합성 180장을 공식 원본과 대조했다. 같은 위치의 배경 픽셀과 동일한 3×3 RGB 패치로 175장의 양쪽 카메라 원본 근거를 찾았다. 174장에 배경 카메라 영역의 99% 이상 픽셀 일치가 확인되어 이진 마스크 후보를 만들었다. 실제 평가에 사용한 20장은 원본·마스크 오버레이를 별도로 검수했다. 공식 JPEG 색상 마스크는 공식 빨강·초록 대표색에 가까운 쪽으로 해석하고, 배경과 다른 카메라 영역을 양성으로 정했다. 모호한 경계 픽셀 비율을 기록했으며 평가에서 제외하지 않았다. 모델 출력으로 정답 영역이나 지도 방향을 고르지 않았다.

COVERAGE는 복제 원본 `*copy.tif`, 원래 가려진 물체 `*paste.tif`, 실제 변조 `*forged.tif`를 구분했다. 공식 `forged` 마스크를 그대로 사용했고 20쌍의 원본·변조·마스크 오버레이를 검수했다. 첫 쌍에서 실제 RGB 변경 픽셀 23,248개가 모두 `forged` 영역에 포함되는 것도 확인했다.

## 3. 자료 확보·분할·선택

[COVERAGE 공식 저장소](https://github.com/wenbihan/coverage)의 공개 OneDrive 폴더에서 `COVERAGE.zip`을 다운로드했다. 자료는 비상업적 연구와 논문 출처 표시 조건이다. 로그인·개인정보 제출·외부 업로드는 하지 않았다.

- ZIP은 148,013,280바이트이며 SHA-256은 `ab9db1fc9caa9e5216a1a2cba1fd24dad6ec2a3071699c90000efaf5f641dbdb`이다.
- 전체 ZIP CRC와 원본/변조 200장·마스크 300장의 누락 여부를 검증했다. 2017-09-27 라벨 수정 README를 확인했고 모든 파일의 SHA-256을 보존했다.
- 변조 이미지와 공식 정답 마스크 크기가 다른 41·48·55·56·57·58·59·61·95번 쌍은 위치 평가용 선정에서 제외했다. 최초 후보 41번 대신 같은 유형의 다음 유효 쌍인 52번을 선택했다. 모든 검수와 교체는 모델 점수를 보기 전에 이루어졌다.
- 선정 쌍은 `1,10,18,15,4,2,8,34,19,31,17,3,11,37,21,52,26,5,40,42`이다. 공식 변조 유형 1~6은 회전·축소 확대·평행 이동·조명·자유 형태·복합이며, 각각 4·4·3·3·3·3쌍이다.
- TIFF를 RGB PNG로 변환하고 공식 Pillow RGB 입력과 픽셀이 완전히 같은지 확인했다. 원본 크기를 유지하고 원본 파일을 보존했다.

Columbia 장면들은 기존 보조 평가에서 이미 노출되었다. 같은 원래 사진의 9개 하위 이미지와 합성 원본 연결을 보수적으로 묶었고, 이미 사용한 20개 원본·20개 합성을 모두 `tune`으로 배정했다. 기존 원본 추론 점수·지도에 검수한 마스크와 새 분할 메타데이터만 붙였으며 GPU 추론을 반복하지 않았다. 재사용 출처와 해시를 기록했다.

COVERAGE 새 20쌍 40장은 모두 `final`이다. 원본과 변조 파생본은 같은 묶음·같은 분할이다. 원래 총량 80장·분할별 양성/음성 20/20을 충족하지만, 원래 의도한 분할 내 데이터셋 혼합은 달라졌다. 이전 Columbia 점수 노출과 장면 공유를 보존하기 위한 조건 변경이며, 분포 차이를 한계로 보고한다.

공식 TruFor 최종 설정의 학습 데이터 목록은 IMD·FR·CA·COCO·RAISE이다. COVERAGE·Columbia가 이 목록에 없음을 확인했지만, 가중치의 모든 사전학습 원본과 픽셀을 대조한 것은 아니다. 학습 자료와의 완전한 독립성을 보증하지 않는다.

## 4. 고정 기준·환경·무결성

공식 기준을 참고한 A를 주 평가로 유지하고 사전 정의한 B를 부 평가로 고정했다. 허용 오탐·미탐·보류 목표가 미합의이므로 서비스 정책은 선택하지 않았다. TruFor A는 `score >= 0.5`, B는 0.40~0.60 양쪽 경계를 포함하는 보류이다. 위치 임계값은 별도 0.5이다.

최종 추론 전에 `trufor_protocol.json`에 목록·추론/정책/평가 코드·공식 소스·최종 가중치의 SHA-256을 고정했다. 고정 파일 SHA-256은 `2eb56539e074d998a56711217c85ebf99e927196c77b128cb07fb2afa915437f`이다. 실행기는 고정 기록이 없거나 목록·코드·가중치가 바뀌면 최종 실행을 거부한다.

환경은 기존 Windows 11·GTX 1080 Ti·Python 3.9.13·격리된 TruFor PyTorch 1.11.0+cu113이다. 공식 소스 커밋 `ae54475df6f41a491d7615100feb19263dec13f7`, 최종 가중치 SHA-256 `ac1d90e329a72e0d66e8665e123a19e94bfae3209c3ef8a4f9ca3b91578c7844`와 `trufor_ph3`를 유지했다. 공식 입력 `/256.0`, 지도 softmax 채널 1, conf·det 공식 sigmoid를 유지했다.

최종 40장 입력 처리 평균은 0.2248초·p95는 0.2807초이다. 첫 입력을 제외한 39장 평균은 0.1876초·p95는 0.2675초이며 최대 GPU 할당은 1019.25MiB이다. 파일 읽기·전처리·GPU 처리·CPU 출력 변환을 포함한 값이며 지도 저장은 별도 `processing_seconds`이다. 서버 지연·CPU·동시 요청 성능은 측정하지 않았다.

9개 단위 테스트가 통과했다. 최종 40장 ID·라벨·입력 해시·지도 크기/범위·NPZ score 일치를 확인했다. 독립 scikit-learn 구현으로 AUROC·20장 IoU·픽셀 F1을 다시 계산해 일치했다. 상세 실패·보류 사례와 유형별 결과는 `trufor_verification.json`이다. 최종 테스트 로그는 `tests_final.log`이다.

## 5. B-Free 상태와 남은 작업

B-Free는 원래 RAISE 실제 40장·Synthbuster 생성 40장 계획을 유지한다. 기존 보조 평가에서 본 RAISE ID 40개를 제외하고 새로운 공통 ID 40개와 생성 모델 배정을 점수를 보기 전에 기록했다. 공식 Zenodo에서 해당 생성 이미지 40개를 59,929,412바이트 부분 전송해 확보했다. 파일별 ZIP CRC·SHA-256을 검증했으며 전체 12.4GB ZIP MD5를 확인한 것은 아니다. 새 이미지의 모델 점수는 아직 수집하지 않았다. 원본 RAISE와의 장면 관계·근접 중복 검수 전에는 조정용/최종 분할을 확정하지 않는다.

[RAISE 공식 안내](https://loki.disi.unitn.it/RAISE/guide.html)는 공식 신청을 통해 받은 CSV의 TIFF/NEF 링크로 선택 이미지를 다운로드하는 절차를 설명한다. 개인정보·약관 동의가 필요한 양식을 거치지 않는 직접 다운로드 요청은 자동 승인 검토에서 거부되었다. 해당 경로로 자료를 받지 않았다. 신청용 이름·소속·이메일·약관 동의 또는 이미 확보한 공식 RAISE-1k 로컬 경로가 필요하다.

실사용 JPEG 재압축·축소·메신저 저장·화면 캡처 파생본, CPU·동시 요청, B-Free 원래 최종 검증과 팀의 서비스 허용 목표 합의가 남았다. 새로운 검증 자료 없이 현재 최종 점수로 임계값을 다시 고르면 독립 최종 검증이라는 의미를 잃는다.

## 6. 재현 자료

실제 실행 자료는 `runs/20261001_original/`에 있다. `coverage_source.json`, `columbia_audit.json`, `columbia_review/`, `trufor_preparation/manifest.csv`, `trufor_preparation/tune_predictions.jsonl`, `trufor_protocol.json`, `trufor_final/predictions.jsonl`, `trufor_final/maps/`, 양쪽 `evaluation/`, `trufor_verification.json`, `tests.log`를 보존했다.
