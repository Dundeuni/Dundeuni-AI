# 변형 입력·CPU Baseline 후속 검증

2026-10-01 현재 VS Code의 Windows 작업 폴더에서 수행한 실험이다. **TruFor 원본 80장에 5가지 조건을 적용한 파생 입력 400장과 두 모델의 CPU 4장씩을 모두 정상 처리했다.** 기존 [원래 구성 결과](ORIGINAL_BASELINE_RESULTS_20261001.md)의 임계값과 최종 결과를 유지했다.

COVERAGE 원본 AUROC 0.8275가 JPEG 재압축·50% 축소·합성 화면 전체에서 각각 0.6625·0.5700·0.4975로 낮아졌다. 동일 표본에서 입력 경로에 따라 탐지 결과가 달라졌다. 실제 메신저 앱·기기 화면 캡처 성능이나 서비스 오류율을 검증한 결과는 아니다.

## 1. 입력 조건과 평가 범위

원본은 Columbia 조정용 40장과 COVERAGE 최종 확인용 40장이다. 동일 원본 80장의 파생본 400장이며 독립 표본 400개로 계산하지 않는다. 원본 묶음·정답·원본 분할은 보존했다. 실행 목록의 `split=exploratory`는 최종 점수 확인 이후의 후속 탐색을 뜻하며, 원본 분할은 `parent_split`에 유지해 아래 표를 분리했다. 새 조정용·최종 확인용으로 재배정하거나 임계값을 조정하지 않았다.

| 조건 | 고정한 입력 처리 |
|---|---|
| JPEG 품질 75 | 원본 크기, 품질 75, 색차 서브샘플링 4:2:0이다. |
| 가로·세로 50% PNG | 각 치수의 정수 절반, 이미지 LANCZOS·마스크 NEAREST이다. |
| 메신저 저장 모사 | 긴 변 최대 512픽셀, 확대 없음, JPEG 품질 80·4:2:0이다. 실제 앱 처리값이라고 주장하지 않는다. |
| 합성 화면 전체 | 720×1280 캔버스에 사진을 640×1000 내부에 맞춰 배치하고 화면 메뉴를 그렸다. 원본에 따라 확대도 포함한다. |
| 캡처 속 사진 영역 | 위 화면의 알려진 사진 배치 좌표로 크롭했다. 자동 사진 영역 검출기는 검증하지 않았다. |

공식 RGB 입력·TruFor 전처리·가중치·지도 방향을 유지했다. 전처리 전 입력 변형만 별도 조건으로 추가했다. 마스크 200개에 동일 기하 변환을 적용하고 이진값·정렬·양성 영역을 확인했다. 지도는 `map >= 0.5`, 전체 픽셀, 양성 이미지별 IoU·F1 평균이다. 지도 반전·경계 제외·평가 중 크기 보정은 없다.

A는 기존 `score >= 0.5`, B는 기존 0.40~0.60 보류 정책이다. 오탐 분모는 음성 20장, 미탐 분모는 양성 20장, 보류 분모는 전체 40장이다. 보류를 성공 판정으로 집계하지 않는다.

## 5. CPU 실행과 GPU 출력 비교

Ryzen 7 5800X에서 모델별 격리 환경과 기존 CPU 기본 스레드를 사용했다. intra-op·inter-op은 모두 8이며 변경하지 않았다. GPU 실험을 마친 뒤 두 CPU 모델을 순차 실행했다.

| 모델 | 입력 | 정상/요청 | 로딩 초 | 평균 초 | p95 초 | 최대 원본 점수 차이 | A/B GPU 판정 일치 |
|---|---|---:|---:|---:|---:|---:|---:|
| B-Free | 공식 예제 4장 | 4/4 | 1.9009 | 10.0510 | 10.3699 | 0.00002432 | 4/4·4/4 |
| TruFor | COVERAGE 1·10번 원본/변조 | 4/4 | 2.4699 | 2.4576 | 2.8022 | 0.00007606 | 4/4·4/4 |

B-Free 원본 점수는 logit이며 정규화 점수의 최대 차이는 약 0.000000404이다. TruFor 원본 점수는 공식 score이다. TruFor 지도와 conf의 최대 픽셀 차이는 각각 약 0.000393·0.000377이다. 1t의 지도에서는 0.5 경계를 넘은 픽셀이 2개 있었다. CPU/GPU 결과가 완전히 동일하다고 주장하지 않는다.

CPU는 모델별 4장의 동작·수치 비교이다. 고해상도 TruFor CPU 처리 시간·전체 평가셋 CPU 성능·메모리·동시 요청·배포 서버 지연은 미측정이다. 이 소규모 평균·p95를 운영 처리량으로 해석하지 않는다.

## 6. 환경·코드·무결성

Windows 11 Home 25H2·RAM 약 32GiB·GTX 1080 Ti 11264MiB·드라이버 582.66에서 실행했다. B-Free는 Python 3.9.13·torch 2.0.1+cu118, TruFor는 Python 3.9.13·torch 1.11.0+cu113이다. 입력 변형은 Pillow 10.4.0으로 생성했다. 기존 Python 환경·드라이버를 바꾸지 않았다.

- B-Free 공식 커밋은 `c6a9f898782fb466b29af01f21960b67415afb0e`이다.
- B-Free 최종 가중치 SHA-256은 `5948ca78f4d94e820c250d24cdf155035b4a85960443800bfe6bb7f06bffe947`이다.
- TruFor 공식 커밋은 `ae54475df6f41a491d7615100feb19263dec13f7`이다.
- TruFor 최종 가중치 SHA-256은 `ac1d90e329a72e0d66e8665e123a19e94bfae3209c3ef8a4f9ca3b91578c7844`이다.
- 기존 최종 목록·코드·가중치 고정 검증을 통과했다. 고정한 추론·정책·평가·프로토콜 코드는 변경하지 않았다.
- 파생 입력 400개·지도 400개·마스크 200개의 메타데이터·해시·크기·범위를 확인했다. 독립 scikit-learn AUROC와 별도 픽셀 집계가 일치했다.
- 경계값·분모·그룹 누출·고정 파일 변경 거부·장면 분할·비대칭 마스크 변환을 포함한 테스트 12개가 통과했다.

## 7. 원본 기록과 남은 작업

기록은 `runs/20261001_robustness/`에 보존했다.

- `conditions.json`과 조건별 CSV는 입력 조건·원본 연결·해시 기록이다.
- `trufor_조건명/`은 조건별 환경·80개 원본 JSONL·지도·conf이다.
- `evaluation/summary.json`과 `paired_changes.json`은 원본 분할별 지표·개별 점수 변화·판정 전환이다.
- `bfree_cpu/`, `trufor_cpu/`, `cpu_verification.json`은 CPU 환경·스레드·원본 결과·GPU 비교이다.
- `tests.log`와 `verification_manifest.json`은 테스트 결과와 코드·주요 산출물 해시이다.

이번 실행에 추론 실패는 없었다. PowerShell 디스크 조회의 0 값은 native Python `shutil.disk_usage`로 재확인했으며 여유 공간은 약 31.7GiB였다. 실제 공간 부족은 아니다.

B-Free 원래 RAISE-1k 실제 40장·Synthbuster 생성 40장 검증은 RAISE 원본 확보 대기이다. 공식 CSV·TIFF 로컬 경로 또는 신청용 이름·소속·이메일·이용약관 동의가 필요하다. 신청 절차 없이 직접 다운로드하는 동작은 자동 승인 검토에서 거부되어 우회하지 않았다. B-Free 입력 변형 검증도 원래 자료 확보 이후에 수행한다.

실제 메신저 앱 저장·기기 화면 캡처·동시 요청·서비스 임계값 선택은 남아 있다. 생성 탐지와 변조 탐지 점수를 합산하거나 사기 확률로 표현하지 않는다. 모든 결과는 로컬에 보존했고 외부 업로드·Git push·학습·서비스 배포는 수행하지 않았다.
